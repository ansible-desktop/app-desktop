0.3.6 (09.10.26)

- The last texts built into the application say Ansible and diamonds: the
  crash and start-up error windows, the Passport reset prompts, the
  autorun and Send To shortcuts on Windows, and exported chat history,
  where prices, gifts and prizes are counted in diamonds - the JSON export
  now names the currency "Diamonds".

- Inside the code the currency is called diamonds as well. Nothing changes
  on screen, but the old name is gone from the source.

0.3.5 (08.10.26)

- The diamond is back. Since 0.3.3 the currency symbol was missing
  everywhere - balances, operation history, gift buttons, Premium prices -
  because the icon was added to the repository but never to the list of
  resources the application compiles in, so there was nothing to draw.

- The round logo is redrawn: it stands in for the service account's photo
  and for hidden notifications, and the square tile looked wrong once the
  app cut a circle out of it.

0.3.4 (07.10.26)

- New artwork throughout: the application icon in every size it is shown at,
  the store tiles, the tray mark, the welcome screen, the QR codes and the
  wallpaper emblem.

- The diamond is drawn properly now, at each screen scale, and so are the
  paid reaction animations and the menu, payment and chat badges that carry
  it.

0.3.3 (04.10.26)

- The currency is a diamond. The icon, the palette and the paid reaction
  badges follow the brand gem instead of the star, and the built-in English
  says Diamonds everywhere the keys already did.

- The photo editor draws a diamond where it used to draw a five-pointed
  star, matching Android and iOS.

- Local data lives in adata, next to aupdates. The folder is moved on first
  launch, so nothing is lost and no one is signed out.

- Theme files are .adesktop-theme and .adesktop-palette. Themes saved or
  downloaded earlier still open.

- Mini apps get our own bridge name, with the previous one kept as an alias
  so existing apps keep working.

0.3.2 (29.09.26)

- The version is read back by our own numbering. 3003002 is 0.3.2, not
  3.3.2: the string goes into tdata/version of the unpacked package and
  Updater.exe writes it into the uninstall entry, so an updated client
  showed the wrong version in Programs and Features. The changelog header
  and the active sessions list read the same place.

- Updates are published under both manifest names the clients ask for:
  current6 on Windows, current2 on macOS and Linux. Windows asked for a
  name that was not there and got a permissions error instead of an
  update, with nothing shown in the interface.

- The release page carries the files: a portable build and the signed
  update package. A run artifact expires and needs a login; a release
  does not.

0.3.1 (27.09.26)

- No functional changes. Cut to verify auto-update end to end on a real
  installation: a client on 0.3.0 should see this version, fetch the
  package from ansible.su/ad, check its signature against our own root
  and apply it on restart. Identical code is deliberate - it isolates the
  update machinery from anything else that could fail.

0.3.0 (25.09.26)

Base and protocol

- Rebase onto upstream Telegram Desktop 7.2.8, API layer 229.
- Single data centre and our own RSA key for the handshake; own api_id.
  The snap build no longer carries someone else's credentials.
- Links are asme.su, deep links are as://, animated stickers are .ass.
  Telegram's t.me, tg:// and .tgs are not recognised, by decision.

Language

- Russian interface, served by the Ansible backend: 7683 of 7683 strings.
- User-visible English strings rebranded.
- Translation key names rebranded: telegram to ansible, stars to diamonds,
  star to diamond, credits to diamonds. 368 keys, client and language packs
  moved in one wave. The star shape in the photo editor and the Gram balance
  strings keep their names - those are not the diamond currency.

Naming

- The source tree no longer carries the upstream name: the Telegram
  directory, the CMake target, the resource files and the package names are
  all Ansible now.
- The hardcoded name is gone from the interface too, including the first
  screen and the watermark burned into every round video message.

Updates

- Auto-update has a root of trust of its own. Until now the client trusted
  Telegram's root key for its own updates and nobody but them could sign one.
- Update packages are built, signed and published by a release lane of ours;
  the client fetches them from ansible.su/ad.
- The update feed lives under /ad rather than /td.

Crash reports

- Crash reporting is enabled again and reports to api.ansible.su/crash.
  Previous builds were compiled with dumps disabled, so a crash left no
  trace at all.

Fixes that were changing behaviour, not just wording

- Applying an update on macOS could never work: the updater was looked up
  inside a bundle named after the upstream product.
- The Windows updater rewrote the installed-program entry back to the
  upstream name and publisher after every single update.
- Laying out our launcher on Linux deleted the real Telegram Desktop's menu
  entry and autostart, if it was installed alongside. The Windows shortcut
  cleanup had the same defect and never found our own shortcut.
- Portable mode migrated the upstream alpha folders into ours, taking data
  that is not ours.
- The autostart toggle in the Store build queried a task that was never
  registered, so it did nothing.
- Forums are available in any group, without the member threshold.
- A phone number typed with spaces, brackets or dashes is accepted.
- The legacy ~/.TelegramDesktop lookup on Linux is gone.
- Our own installer identifier, so the two applications no longer overwrite
  each other's install entry on Windows.
- The version is set from one place and cannot drift between the executable,
  the installer and the running application.
