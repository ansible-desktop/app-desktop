# Переход на 0.3.0

Версия 0.3.0 — первая сборка на базе upstream 7.2.8 (слой 229) с полностью
нашими именами ключей переводов. Здесь описано, что происходит при переходе
с предыдущих сборок, что переносится, а что нет.

## Коротко

| | |
|---|---|
| Предыдущая линия | 0.2.0 (внутреннее число 3002000) |
| Эта версия | 0.3.0 (внутреннее число 3003000) |
| База upstream | 7.2.8, слой API 229 |
| Переустановка поверх | да, данные сохраняются |
| Повторный вход | не требуется |
| Автообновление | **не работает**, см. ниже |

## Как обновиться

🚨 **Кнопка «Обновить» внутри приложения сейчас ни к чему не ведёт.** Клиент
опрашивает `https://ansible.su/td/current2` (значение по умолчанию задано в
`storage/localstorage.cpp`), а на этом адресе ничего не опубликовано —
приходит 404 страницы сайта. Проверка молча заканчивается ничем, и
приложение остаётся на прежней версии, **не сообщая об этом**. Пока сервер
обновлений не подключён, единственный путь — скачать сборку и поставить её
поверх.

Порядок:

1. Закрыть Ansible Desktop полностью (проверить, что значка в трее нет).
2. Поставить новую сборку в тот же каталог, что и прежнюю.
3. Запустить. Вход, чаты, кеш и настройки остаются на месте.

Каталог данных не трогать: на Windows это `%APPDATA%\Ansible Desktop\tdata`.

## Что переносится

**Сессия и локальные данные.** Формат хранения не менялся, внутреннее число
версии растёт (3002000 → 3003000), поэтому файлы читаются как есть. Выходить
из аккаунта и входить заново не нужно.

🚨 Внутреннее число версии **обязано** оставаться не ниже 2008007. Сборка с
меньшим значением прочитает собственные данные по устаревшей ветке
`readPeer()`, и свой же аккаунт после перезапуска отобразится ботом. Именно
поэтому версию ставит скрипт (`Telegram/build/set_version.py`), а не руки:
он считает число по схеме форка и отказывается записать значение ниже порога.

**Переводы.** Приезжают с сервера, в сборку не вшиты (кроме встроенного
английского). После первого запуска клиент заберёт пак заново, потому что в
этой версии **изменились имена 368 ключей**.

## Что важно знать про имена ключей

В 0.3.0 переименованы имена ключей переводов: `telegram` → `ansible`,
`stars` → `diamonds`, `star` → `diamond`, `credits` → `diamonds`.

🚨 **Клиент и языковой пак обязаны совпадать по версии.** Несовпадение не
даёт ошибки: `lang_instance.cpp` при разборе пака просто пропускает ключ,
которого не знает, и пишет об этом только в `DEBUG_LOG` — в релизной сборке
этой записи нет. Наружу это выглядит как «часть интерфейса вдруг
по-английски», без единой записи в журнале.

Отсюда два случая, и оба временные:

- **новый клиент, старый пак на сервере** — 368 строк показываются
  по-английски во всех языках;
- **старый клиент, новый пак** — те же 368 строк откатываются на встроенный
  английский, когда приедет дельта с надгробиями.

Поэтому клиент и сид сервиса переводов выкатываются **одной волной**. Проверка
после выкатки — не «пак загрузился», а пересечение множеств: сколько новых
имён реально есть в паке (должно быть 368 из 368).

Дельта переименования — около 750 строк, это больше предела `PUSH_MAX_STRINGS`
(500) в `langpack_source.erl`, поэтому клиенты получат `updateLangPackTooLong`
и запросят полный пак сами. Это штатное поведение, а не сбой.

## Отчёты о падении

В 0.3.0 отчёты включены обратно и приходят к нам, на
`api.ansible.su/crash`. Прежние сборки собирались с
`DESKTOP_APP_DISABLE_CRASH_REPORTS=ON`, то есть дампы у них не создавались
вовсе: падение проходило бесследно.

Что приезжает: текст отчёта и, если он был создан, сжатый minidump. В тексте
уже лежит готовый диагноз, если сработала внутренняя проверка — условие и
`файл:строка`. Символы (PDB) сборкой не публикуются, поэтому по адресам
разбирается только то, что попало в текст.

🚨 В minidump лежит **дамп памяти клиента**: куски переписки, токены сессии,
путь к каталогу данных. Срок хранения и круг доступа к этим файлам ещё не
назначены; до решения они складываются в отдельный префикс `crash/`, чтобы
чистка была одной операцией.

## Совместимость с Telegram Desktop

Ansible Desktop не открывает `t.me`, `tg://` и `.tgs` — это не упущение, а
решение: мы не Telegram и не выступаем его совместимым клиентом. Свои
ссылки — `asme.su`, своя схема — `as://`, свои анимации — `.ass`.

Идентификатор установки у нас собственный, поэтому Ansible Desktop и
Telegram Desktop больше не перезаписывают друг другу запись об установке в
Windows и могут стоять рядом.

На Linux прежний просмотр каталога `~/.TelegramDesktop` убран полностью:
если такая папка осталась от Telegram Desktop, мы в неё не заглядываем.
